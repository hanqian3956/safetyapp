任务模块 · 逻辑备注（开发用）

页面只保留用户可见内容；实现口径全部写在这里。演示时钟固定 DEMO_NOW='2026-07-14 09:30'，文中"当前时间"均指它，保证超期标记可复现。

1对象模型与标识

对象产生方式说明
模板PC 设计器低代码表单 + 全局规则；界面只展示 TPLxxx
任务一次发布单次只生成 1 条执行；周期按规则持续生成
执行到点生成有自己的计划起止，超期按它自己算
待办执行 × 执行人会签最小单位，一人一条、独立提交

执行编号是唯一在界面展示的业务编码：任务名称首字母 4 位 + yyyyMMdd + 3 位流水号，例 WSND20260702001（瓦斯浓度监测 · 2026-07-02 · 当日第 1 条）。流水号按「前缀 + 发布日」自增，跨天重置；生成即固化，改名不改号。任务编号、待办 ID 仍只在后台与导出中使用；模板编码 TPLxxx 继续展示。

原型里用「名称→首字母」映射表近似生成演示编号（未收录的名称回退到来源模板前缀，再兜底 RWXX）；真实实现请用拼音库生成并由服务端落库。

渲染数据全部来自 TASKS / EXECS / DRAFTS / TEMPLATES 常量，页面字段逐条对应其属性，见下文各表。

2我的任务 · 卡片字段来源

以「待我执行」里的「瓦斯浓度监测」为例（EXECS 中 I20260701007）：

任务名称← exec.name，该次执行所属任务名，发布时快照；>20 字截断加「…」
执行编号← exec_no，生成执行时由服务端按「名称首字母 4 位 + 发布日 yyyyMMdd + 3 位流水号」生成并固化，后续改名不变；卡片标题上方单独一行 10px 等宽浅灰小字（# 前缀），不占标题行、不与状态标签抢位。示例 WSND20260702001
发布时间← exec.pubTime，该执行被生成的绝对时刻＝它的计划开始 − 提前量；周期任务每天一条，各不相同。示例值 2026-07-02 08:00
执行人← 该执行全部执行人（signers 去掉已转出的），含我；1 人全名、2 人「A、B」、≥3 人「A、B 等 N 人」。示例值「张伟明」
状态← 服务端按 已提交人数/执行人总数 计算：0 → 未执行；0<n<m → 执行中 n/m；n=m → 已完成。本标签不会出现已完成（我一交就移出）。示例：0/1 → 未执行
超期← 人级判定：我未提交 且 当前时间 > 该执行 planEnd → 红「超期」。示例：我未交，2026-07-14 09:30 > 2026-07-02 12:00 → 超期
超期完成← 我已提交但 我的提交时间 > planEnd → 橙「超期完成」，永久保留。出现在「已执行」
未到计划开始← 任务规则 rule.execCtrl=true 且 当前时间 < 该执行 planStart → 执行按钮置灰，卡片提示「未到计划开始时间（完整年月日时分，如 2026-07-14 10:00）」。演示数据：顶板离层专项观测（I20260714002，plan_start=2026-07-14 10:00）

「执行」按钮点击＝进入执行页；「转办」＝打开转办弹窗。超期只标红和提醒，不限制提交 / 转办。

3我的任务 · 四个标签的差异

标签行粒度超期口径操作
待我执行我的待办人级：我未交且过期执行 · 转办
已执行我的待办人级：我的提交 > plan_end → 超期完成查看（我的提交只读页）
已转发我的待办不显示（进度归接手人）查看（任务详情）
我参与的整条执行执行级：未闭环且过期查看（任务详情）

互斥归属：未交 → 待我执行；已交 → 已执行；已转出 → 已转发；仅参与 → 我参与的。同一执行同一人只出现一次。

「已转发」字段：转给 ← signers[CU].fwdTo；转出时间 ← fwdAt。「已执行」字段：我的提交时间 ← signers[CU].at（服务端提交时刻）。「我参与的」执行人列不含我（我是参与人）；执行被撤回 / 作废后从本列表移除。

排序：待我执行超期在前，其余按发布时间倒序。四类卡片（含已转发、我参与的）都展示执行编号，现场可直接按编号口述、搜索。

4发布任务 · 我发起的 字段来源

类型← task.rule.repeatOn：开＝周期，关＝单次
执行人← task.execs（任务全部执行人，人员显示规则同上）
已发布次数← count(EXECS.filter(taskId))；0 次纯文本不可点，≥1 次为链接，点开执行明细
状态← 任务级 4 态（服务端下发）：进行中 / 已暂停 / 已完成 / 已终止；任务级不出现超期。注意「已完成」只代表执行已全部生成完毕，不代表做完
创建时间← task.createdAt＝任务定义的创建时间：直接发布＝点发布的时刻；先存草稿后发布＝草稿创建时间，发布不改变它（例：10-23 10:00 建草稿、10-25 08:00 发布 → 显示 10-23 10:00）。首条执行的发布时间在执行明细的「发布时间」列看；列表按创建时间倒序

范围：creator = 当前登录人。操作：进行中＝编辑计划·暂停·复制·终止；已暂停＝编辑计划·恢复·复制·终止；已完成/已终止＝查看·复制。编辑计划只影响之后生成的执行；终止需填原因 2–200 字。

5执行明细 / 执行详情

入口：我发起的 → 点「已发布次数」。范围限自己发起的任务，按发布时间倒序；每行首位同样显示执行编号，与卡片同源。

发布时间← exec.pubTime（同上）
执行人← signers 去掉已转出的
状态← 已提交人数 / 执行人总数；必须带 n/m
超期← 执行级：未闭环 且 当前时间 > plan_end → 超期；闭环 且 最后提交 > plan_end → 超期完成；已撤回 / 已作废 → 不显示
操作← 详情恒有；撤回仅 0/n；作废仅 0<n<m；调整仅存在未提交者且目标≠现有执行人。撤回 / 作废必填原因 2–200 字；撤回不通知、作废通知、调整通知新旧执行人；都写执行日志

执行日志行（任务详情同源）：系统·已发布（←pubTime）/ 各执行人 已提交（←signer.at，标人级超期）/ 未提交（置顶）/ 事件行：已转办（←signer.fwdTo / fwdAt / fwdReason）、已撤回、已作废、已调整执行人（←exec.events）。未提交置顶，其余按时间倒序；动作颜色：提交绿、转办蓝、撤回橙、作废红、调整紫。

「查看提交」＝进入该执行人的只读提交页；撤回 / 作废后提交记录与日志保留，仅从统计剔除。

6执行任务页 字段来源

状态条状态 ← 服务端（n/m）；超期徽标 ← 人级判定；只读态标题换「查看提交 · 姓名」
执行编号← execNo(e)，只读展示在基本信息第一行（等宽字体），执行页与任务详情、执行详情三处一致，用于现场口述与拍照留痕
发起人← task.creator
执行人← 该执行全部执行人（含已提交者）
参与人员← exec.parts（不产生待办）
执行表单← 模板快照 form；无表单显示「无（普通任务）」
工种 / 地点← task.work / task.loc，发布时快照
计划时间← 该执行自己的 plan_start ~ plan_end（跨天补日期），不是任务整体起止
执行说明← task.desc，单独占一整行

填写区：无表单 → 「执行完成情况」必填 + 附件（≤9 个、单个 ≤20MB）；有表单 → 按模板 components 渲染（原型里巡检区域等是演示字段，开发不要写死）。

提交：校验 → 写 signers[CU].at（服务端时间）→ 行移入已执行并写「我的提交时间」→ 静默返回；会签未满显示执行中 n/m。暂存存本地 EXEC_DRAFTS，不改状态、再次进入回填。转办：我的待办置已转出、给接收人生成新待办、移入已转发。开始时间控制：exec_ctrl 开且 now < plan_start 时按钮置灰，服务端同样拦截。

7发布表单 · 基本信息来源与校验

任务名称默认＝模板名，可改；必填
发起人＝当前登录人，只读
参与人员组织架构多选，模板默认值；不产生待办、不参与会签
执行人组织架构多选，模板默认值；≥1 人，产生待办
执行表单模板带入（无 / 普通业务表单 / BPM）；发布后不可改
工种 / 地点 / 说明模板默认值，可改
计划起止默认次日 08:00~17:00；含义＝第一条执行的起止；校验：结束 > 开始、开始 ≥ 当前时间；后续执行＝日期按频率后推，时刻与时长沿用首条

发布成功：创建任务（生成编号）→ 生成首条执行 → 跳「我发起的」。存草稿：只存定义不生成执行。编辑计划：只改任务定义，已生成的执行不回改。复制：照抄配置新建，名称加「（副本）」，所有状态可用。

8全局规则 · 字段与默认值（与 PC 一致）

执行控制 execCtrl：默认开。开＝未到该执行 plan_start 不能提交（服务端同校验）；关＝收到待办即可执行。

自动推送提醒 remindOn：默认开。关＝三类提醒全不发。

计划开始前 beforeStart：多选，准时 / 提前10分 / 30分 / 1小时 / 2小时 / 1天 / 2天 + 自定义（1–999 分钟·小时·天）；选项中没有「不提醒」，全部取消＝该提醒不发；多选时每个选项各发 1 次；触发时刻＝plan_start − 提前量。提醒人 beforeStartPersons 默认＝执行人，可单独改，≥1 人。

计划结束前 beforeEnd / beforeEndPersons：同上，基准＝plan_end。

超期未处理 overdue：单选，每10分 / 每30分 / 每1小时 / 每1天 + 自定义「每N单位」；选项中没有「不提醒」；未选择时字段显示「请选择」、内部状态记为 不提醒（未配置），此时重复次数不可编辑；选定后按该间隔重复，第 1 次提醒＝plan_end + 间隔；重复次数 overdueCount 1–10 默认 2（总发送次数含第 1 次），在「超期未处理」下拉弹层内配置，与 PC 端一致；提醒人 overduePersons 默认＝执行人。

重复发布 repeatOn：默认关；开＝按频率持续生成执行。

频率freq：按天 / 周 / 月 / 年；没有「不重复」选项，是否重复由开关决定
重复日期按天＝每天；按周 week＝星期多选（下拉弹层，含全选 / 清空）；按月 month＝1~31日 + 最后一天（按当月实际天数取，2月28/29）；按年 yearRows＝多行「月份 × 日期」下拉多选，行内笛卡尔积，行 ≤10，无效日期（2/30 等）自动跳过
停止日期stopDate ≥ 首条日期；noEnd 永不截止；到点后任务转「已完成」，不再生成
发布时间delay：准时 / 提前1小时 / 2小时 / 1天 / 2天 / 自定义；发布时刻＝计划开始 − 提前量
立即发布imm：默认关；开＝保存 / 发布时立刻生成第一条，不等发布时间

发布前校验顺序：名称 → 执行人 ≥1 → 起止有值 → 结束 > 开始 → 开始 ≥ 当前时间 → 重复日期 ≥1 → 停止日期 → 各类提醒人 ≥1。规则改动只影响本次发布，不回写模板；模板默认值带入，发布时可覆盖。「下一次任务详情」按当前填写值实时推算下一条的发布时间与计划起止。

9只读与边界

  • 留 PC：模板设计 / 启停 / 删除；任务总台账（全域视图 / 导出 / 跨人暂停终止撤回作废调整）。
  • 移动端只读：任务详情、执行详情、执行明细、提交详情。
  • 模板：只在「发布时选择」出现；不展示来源模板，不提供任何模板管理。
  • 一期无审批：提交即闭环，表单数据进业务台账。
  • 角色：普通执行者隐藏「发布任务」段；按钮权限由服务端按角色 × 关系 × 状态下发。

10移动端交互约定（开发实现要求）

  • 主操作吸底：「发布 / 提交」固定在页面底部操作条，右侧主按钮占 68%、高 42px；左侧次要按钮（存草稿 / 暂存）占 32%。只读态整条隐藏，滚动区自动占满。
  • 头部两层：标题行内放「我的任务 / 发布任务」分段（单角色时降级为标题文字），其下才是页签 + 筛选图标；头部总高控制在 90px 内，不再堆三层。
  • 整卡可点：点卡片任意位置进详情 / 编辑，卡片内按钮与「已发布次数」链接必须 stopPropagation，避免误触。
  • 操作收敛：卡片最多 2 个按钮；暂停 / 恢复 / 复制 / 终止、编辑 / 删除草稿一律收进「更多」底部弹层，危险项置底且标红。
  • 触控尺寸：卡片按钮高 32px，吸底主按钮 42px，图标按钮 30–32px；文字链改为整行可点，不再使用 11px 行内文字。
  • Toast：距底 92px 居中，避免遮挡头部与吸底操作条；页面用 100dvh 适配移动端浏览器地址栏。
  • 执行编号：卡片标题上方、执行明细每行标题上方、执行页/任务详情/执行详情基本信息第一行，四处同一取值；等宽字体、10px、浅灰（#93a2b5），只做弱提示，不抢标题。
